# Mario-Play Implementation Plan

> **For agentic workers:** this plan is executed by a multi-agent workflow. Each
> agent implements exactly one task below, using TDD, inside a shared working
> tree with disjoint file ownership. Read the spec first, then your task.

**Goal:** an original Mario-style platformer, a Gymnasium env around it, and a
from-scratch PyTorch RL framework (PPO + Double DQN) with full train/eval tooling.

**Architecture:** headless-first pure-Python/numpy simulation; one numpy
framebuffer renderer shared by humans (pygame window) and agents (pixel obs);
Gymnasium env with pixel and grid observations; RL framework where one trainer
loop drives any `Algorithm` (`select_actions → step → observe → update`).

**Tech stack:** Python ≥ 3.10, numpy, gymnasium ≥ 1.0, torch ≥ 2.2, pygame-ce,
pyyaml, tensorboard, pillow; pytest, pytest-timeout, ruff; uv; GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-09-19-mario-rl-design.md` — authoritative
for behaviour. Where real upstream code and the spec disagree on a signature,
follow the real code and report the deviation.

**Deviation from the plan template:** tasks list exact interfaces, required test
cases and acceptance commands instead of pre-written code; implementers write
the code test-first.

## Global Constraints

- Use `.venv/bin/python`, `.venv/bin/pytest`, `.venv/bin/ruff`. Never run
  `uv sync`, `uv add`, `pip install`; never edit `pyproject.toml` or `uv.lock`.
  If a dependency is missing, report it instead.
- Never run git commands that change state (add/commit/stash/checkout/reset).
  The orchestrator commits.
- Create/modify only the files in your task's **Files** list. Exception: a
  minimal fix for a clear bug in an already-finished upstream file — re-run that
  module's tests and describe the fix in your report.
- Never edit any `__init__.py` (they are lazy contract files). Import from
  concrete modules (`from mario_play.game.engine import Game`), never from
  package-level re-exports.
- `mario_play.game` must not import gymnasium, torch or pygame (only
  `game/human.py` may import pygame, lazily inside functions).
  `mario_play/__init__.py` stays import-light.
- All tensors float32 (MPS has no float64). No global RNG use in the game:
  only `Game.rng`.
- No Nintendo assets, sprites, level layouts or names: `Player`, `Walker`,
  `Turtle`. All art and levels are original.
- TDD: failing test first. Tests deterministic; every non-slow test file runs
  in < 10 s; longer tests get `@pytest.mark.slow`. Tests never open a real
  window (`SDL_VIDEODRIVER=dummy`).
- Public functions/classes have type hints and docstrings. Comments only where
  the *why* is non-obvious. Ruff-clean at line length 100:
  `.venv/bin/ruff check <files> && .venv/bin/ruff format <files>`.
- Final report (your return value): files written, test command + pass count,
  contract deviations, upstream fixes, known gaps. Report failures honestly.

### Task G1: Game core

**Files:** `src/mario_play/game/{constants,tiles,level,entities,physics,engine}.py`,
`src/mario_play/levels/{flat,1-1,1-2,1-3}.txt`,
`tests/game/test_{level,physics,rules,engine,determinism}.py`.

**Consumes:** nothing (numpy only).
**Produces:** everything in spec §3.1–3.5 with those exact names and signatures:
`Tile`, `SOLID`, `Spawn`, `Level`, `load_level`, `list_levels`, `Entity`, `Player`,
`Walker`, `Turtle`, `Mushroom`, `Buttons`, `StepEvents`, `Game`. Entities expose
`x, y, w, h, vx, vy, alive, kind, facing`; `Player` adds `big, on_ground,
invuln_frames, dead`; `Walker.squished_frames`; `Turtle.state`.

Required tests (names indicative, behaviour mandatory):

- level: parses every legend char; pads to 15 rows; pipe lip detection; topmost
  `F` → `FLAG_TOP`; metadata `; time=`; each error case raises `ValueError`
  (missing `S`, missing `F`, unknown char with line/col, > 15 rows, width < 16);
  `list_levels()` returns the four bundled names and each loads; `copy()` is
  independent; `solid_at` out-of-bounds semantics.
- physics invariants (spec §3.1): standing full-hold jump apex 3.5–4.5 tiles; tap
  jump ≤ 2 tiles; running full-hold jump ≥ 6 tiles horizontally; walk/run top
  speeds; no tunnelling at terminal velocity or run speed; player stops flush
  against walls/floors/ceilings; left screen edge blocks the player.
- rules: coin tile collection; `?` bump gives a coin and becomes `USED`; `M` bump
  spawns a mushroom that makes the player big with feet fixed; brick breaks
  only when big; stomp squishes a walker and bounces the player; side contact
  kills small / shrinks big with 120 invulnerable frames; turtle → shell →
  kicked shell kills a walker → stomp stops it; enemies reverse at walls and
  each other and fall off ledges; dormant spawns activate at
  `spawn_x < camera_x + 384`; pit death; timeout death; flag win; `step` after
  `over` is a no-op; camera never scrolls left; score values.
- determinism: same seed + button sequence ⇒ identical `snapshot()` per frame;
  `clone()` then diverging inputs do not affect the original; clone continues
  identically to the original under the same inputs.
- fuzz: 20 seeds × 3000 random-button frames on each bundled level — no
  exception, no NaN, player never inside a solid tile, `x` within level bounds.

Levels: original layouts satisfying spec §3.3 (sizes, max pit widths, no 1-tile
corridors, flag reachable). `1-1` must be finishable by holding right+run and
jumping sensibly; keep a comment header in each file describing its intent.

### Task P1: Rollout buffer and PPO

**Files:** `src/mario_play/rl/buffers/rollout.py`, `src/mario_play/rl/algos/ppo.py`,
`tests/rl/test_{rollout_buffer,ppo}.py`.

**Consumes:** T0 `Algorithm`, `VecStep`, `TrainConfig.ppo`; N1 `ActorCritic`.
**Produces:**

```python
class RolloutBuffer:
    def __init__(self, n_steps, n_envs, obs_shape, obs_dtype, device)
    def add(self, obs, actions, log_probs, values, rewards, dones) -> None
    def compute_returns_and_advantages(self, last_values, last_dones, gamma, gae_lambda) -> None
    def minibatches(self, n_minibatches, generator=None) -> Iterator[dict[str, Tensor]]
    full: bool; def reset(self)
class PPO(Algorithm)     # spec §6.4
```

Semantics: `dones[t]` is the done flag of the transition stored at `t`
(`terminated | truncated`); truncation bootstrapping adds `γ·V(final_obs)` to the
stored reward for envs with `truncated & ~terminated`. `update()` bootstraps
from the obs/done seen in the last `observe`. `state_dict` holds model,
optimizer, update counter. LR anneal: `lr · (1 − progress)` when `anneal_lr`.

Tests: GAE equals a hand-computed example including a mid-rollout done and a
truncation; λ=1 equals discounted Monte-Carlo returns minus values; minibatches
partition all `n_steps·n_envs` samples exactly once per epoch; `ready_to_update`
only when full; buffer resets after update; update returns all metric keys with
finite values; first-epoch `approx_kl ≈ 0` and ratio ≈ 1; LR anneals;
`target_kl` early stop; `state_dict` round-trip reproduces identical `predict`
and identical next update (same RNG); on a 2-armed bandit-like `CountingEnv`
variant or CartPole 5 k steps, mean return improves (fast sanity, CPU).

**Acceptance:** `.venv/bin/pytest tests/rl/test_rollout_buffer.py tests/rl/test_ppo.py -q` green; ruff clean.
